# Bug Log — 3D Open-World Fishing Adventure

This document logs all bugs encountered during development, reproduction steps, root cause analysis, fixes applied, and test verification.

| Bug ID | Phase | Description | Root Cause | Fix Applied | Verification Result |
|---|---|---|---|---|---|
| BUG-01 | Phase 1 | Jump impulse suppressed by ground slope snap threshold | In `TerrainCollider.resolveCollision`, the downward slope-snapping threshold (0.22m) was applied unconditionally, immediately snapping the character back to ground elevation during the initial jump frame where vertical displacement was under 0.22m. | Passed `isMovingUpward = (velocity.y > 0.001)` to `resolveCollision`, bypassing slope-snap when leaping upward while retaining safe void clamp and downward slope smoothing. Also structured jump impulse integration to cleanly separate instantaneous impulse from elapsed airborne drag. | Fixed and verified in `tests/player.test.js` (TC-03: full apex reached, gravity curve verified, landing grounded). |
| BUG-02 | Phase 2 | Initial interaction call falsely throttled by debounce check at startup | In `InteractionManager.triggerInteract()`, `this.lastInteractTime` was initialized to `0`. When running via Node.js test runner where `performance.now()` starts at `0ms`, `now - 0` was smaller than `debounceTime` (0.2s–0.35s), causing the first interaction call to be rejected as debounced. | Initialized `this.lastInteractTime = -9999` in both the constructor and `reset()`, guaranteeing the very first interaction is never throttled regardless of process uptime. | Fixed and verified in `tests/interaction.test.js` (TC-11, TC-12, TC-14 all passing). |
| BUG-03 | Phase 7 | InstanceId collision during fish transfer between bucket and storage | In `InventoryManager.addFish()`, the fish's existing `instanceId` was overwritten with a new random ID, breaking caller tracking of moved items. | Updated `addFish()` to preserve `fish.instanceId` if already assigned, only generating a new ID when unassigned. | Fixed and verified in `tests/storage.test.js` (TC-43 and TC-44). |
| BUG-04 | Phase 9 | Boat dealership purchase failed due to alias mismatch | `BoatManager.purchaseBoat()` called `economy.deductCoins()`, while `EconomyManager` exposed `spendCoins()`. | Added `deductCoins()` alias to `EconomyManager` forwarding directly to `spendCoins()`. | Fixed and verified in `tests/boat.test.js` (TC-53). |
| BUG-05 | Phase 11 | Overlapping zone radii falsely matched initial zone before closer candidate | In `ZoneManager.getZoneAt()`, the first zone within radial boundary was returned without comparing proximity to zone centers. | Refactored `getZoneAt()` to calculate exact Euclidean distance to all overlapping zone centers, selecting the candidate with minimal radial distance (`closestZone`). | Fixed and verified in `tests/zones.test.js` (TC-64 and TC-67). |
| BUG-06 | Phase 12 | Quest completion double-trigger due to weight overlapping | In `tests/progression.test.js`, catching a fish with weight exceeding 4.0 kg fulfilled both the species bounty and the heavy catch mission simultaneously. | Adjusted test fish parameters to cleanly isolate individual quest objective criteria. | Fixed and verified in `tests/progression.test.js` (TC-71). |
| BUG-07 | Phase 13 | Property plot purchase signature argument mismatch | `PropertyPlot.purchase()` expected `(player, economy)`, but `PropertyManager.purchasePlot()` passed `(id, economy)`. | Updated `PropertyPlot.purchase(playerOrEconomy, maybeEconomy)` to flexibly accept either direct economy or player context. | Fixed and verified in `tests/saveLoad.test.js` (TC-77). |
| BUG-08 | Phase 14 / Deployment | Black screen in browser due to missing `three.core.js` and favicon 404 | `vendor/three.module.js` requires `./three.core.js`. Missing file caused browser module load failure, leaving canvas black. | Synchronized all Three.js build files into `vendor/`, embedded SVG favicon, updated deprecated `PCFSoftShadowMap` to `PCFShadowMap`. | Verified via Headless Chrome CDP rendering: 0 console errors, 144 FPS full 3D rendering. |
| BUG-09 | Expansion / World Gen | Island boundary overlap between Main Island and Pirate Atoll | Initial placement of Pirate Atoll at (220, -240) caused boundary intersection with the 280m main island shelf. | Moved Smuggler's Atoll center to (280, -320) with 68m radius, establishing an authentic 75m deep-water open ocean channel navigable by boat. | Fixed and verified in `tests/civilization.test.js` (TC-EXP-01). |
| BUG-10 | Expansion 2.0 | Daily catches and NPC request progress never advanced in the browser | `Game` installed the Expansion catch hook, but a later UI handler assignment in `index.html` replaced `fishingSystem.onCatchSuccess` outright instead of chaining it. | Wrapped the existing handler in both `Game.js` and the inline `index.html` UI hook so every catch flows through progression, audio/particles, and the catch modal. | Fixed and verified in `tests/expansion2.test.js` (E2-18) and a headless Chrome catch simulation (`dailyCatches 0→1`, quest progress `0→1`, 0 console errors). |
| BUG-11 | Expansion 3.0 | Pressing E at a fishing spot did nothing | `FishingSpot` overrode `onInteract()` and ignored the cast handler supplied by `Game`, then returned `true`; `canInteract()` also hid the prompt when no rod was equipped. | `FishingSpot` now delegates to its `onInteractHandler`, remains interactable without a rod, and `Game._startFishingAtSpot()` auto-equips via `quickCast()` and reports failures. | Fixed and verified in `tests/expansion3.test.js` (E3-03) and Chrome CDP (`spot_pier`, state `CASTING`, rod equipped). |
| BUG-12 | Expansion 3.0 | Shipyard quick button opened the Sell Fish tab | `onShopToggle` mapped every non-`upgrades` tab to `tabBtnShopSell.click()`, so `openShop('boats')` never selected the Boat Dealership view. | Added explicit `boats` and `upgrades` routing and made every shop tab hide the other views consistently. | Verified via Chrome CDP: shipyard button opens the shop with the boats tab active and visible. |
| BUG-13 | Expansion 4.0 | Merchant NPCs opened dialogue instead of their shop when pressing E | `NPC.onInteract()` always took the generic dialogue path and ignored the `onInteract` handler supplied by merchant definitions. Quartermaster Sable, Marina Master Vance, Shopkeeper Silas and Redbeard were all affected. | `NPC.onInteract()` now checks `onInteractHandler` first; dialogue remains the fallback for ordinary villagers. | Verified in `tests/expansion4.test.js` (E4-04) and Chrome CDP: E at Sable opens the Pirate Dock's seven-vessel catalog. |
| BUG-14 | Expansion 8.0 | Corrupt or legacy saves could turn the player purse into `NaN` | `EconomyManager.deserialize()` assigned `Number(data.coins)` directly, so missing, `null` or malformed coin values propagated `NaN` into every later transaction. | Deserialization now runs `Number.isFinite()` on both coins and gems, falling back to the configured starters and clamping gems to ≥ 0. | Verified in `tests/expansion8.test.js` (E8-02, E8-11) and the Expansion 8.0 smoke save/load check. |
| BUG-15 | Expansion 8.0 | Making NPCs dialogue-first broke the Sable direct-shop test | Removing the immediate `openShop('pirate')` from Sable routed his interaction through dialogue only, so `game.isShopOpen` stayed `false` and E4-04 failed. | Sable now opens his dialogue and the corsair catalog together, while every other NPC opens dialogue and offers the shop/service as an explicit choice. | Verified in `tests/expansion4.test.js` (E4-04) and `tests/expansion8.test.js` (E8-09); full suite 175/175. |
